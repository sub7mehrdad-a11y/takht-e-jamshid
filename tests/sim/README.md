# شبیه‌سازِ بازیِ کامل

یک گرداننده + N بازیکن، هر کدام یک صفحهٔ واقعیِ Chrome که با DOM واقعیِ `index.html` کار می‌کند.
به‌جای Supabase یک پایگاه‌دادهٔ درون‌حافظه‌ای (`mockdb.js`) می‌نشیند، پس `supabase-client.js`، `resolveNight.js` و
خودِ UI **بدونِ هیچ تغییری** اجرا می‌شوند. چند بازیِ کامل (روز ← رأی ← مجلسِ مهان ← تصمیم ← شب ← حل ← روزِ بعد ← پایان)
را با انتخاب‌هایِ تصادفی (با seed ثابت) بازی می‌کند و هر جا چیزی با قوانین نخواند، `ISSUE` چاپ می‌کند.

```bash
cd tests/sim
npm i
node sim.js <شناسهٔ چیدمان> <seed> [حداکثر دور]    # مثلاً: node sim.js 12a 1 14
FORCE=enchantZ node sim.js 13a 21 18                # سودابه هر شب ضحاک را افسون کند
NORELOAD=1 node sim.js ...                          # بدونِ آزمونِ رفرشِ صفحه
```

چیزهایی که چک می‌شود: تخصیصِ نقش‌ها، صفحهٔ هر بازیکن در هر فاز (بازیکنِ حذف‌شده = ناظر)، رأی‌دادن و تابلو،
جامِ جم/زندان/اهریمن/سروش، مجلسِ مهان اجباری، زندانی نکشتن، نوشدارو (سهراب/کینِ سیاوش)، سیاوشان، ترتیبِ کارت‌هایِ شب
(سودابه اول)، ضحاکِ افسون‌شده، ضحاکِ ناتوان، پیوستنِ سهراب، هفت‌خان (فقط ارجاسب)، تحویلِ نامه، پایانِ بازی،
و بازگشتِ صفحه بعد از رفرشِ گرداننده/بازیکن.

## بانکِ بزرگمهر (دریک)
```bash
BANK=1 node sim.js 12a 121 14       # سرورِ واقعیِ واژو (../واژو/server) + دیتابیسِ ساختگیِ همین شبیه‌ساز؛ ۴ بازیکن با حساب وارد می‌شوند، با ۵ دریک شرکت می‌کنند (یکی با موجودیِ ناکافی)،
                                    # بازی تمام می‌شود و استخر/پاداش‌ها/موجودیِ سرور و صفحه با هم تطبیق داده می‌شود
node tests/sim/bank-ui.js           # رابطِ بانک: ثبت‌نام، کدِ بازیابی، پاداشِ روزانه، خروج/ورود، بازیابی، ماندگاری، حذفِ حساب (Chrome + سرورِ واقعیِ واژو)
STORE_SHOTS=پوشه node sim.js 12a 121 14   # اسکرین‌شاتِ ۳۶۰×۶۴۰×۳ برایِ فروشگاه (با BANK=1 صفحه‌هایِ بانک هم می‌آید)
```
